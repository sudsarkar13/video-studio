## Tagline (one line)

Make product demos, reels, launch and tutorial videos from your app, blog or images: open-source voices, generated music, all local.

## Short description

Turns a web app, an article or a set of images into a finished, narrated MP4. It writes the script, records your app live, adds a voiceover and royalty-free music, and renders 16:9 or full-screen iPhone 9:16. Everything runs locally with open-source tools. Tested on macOS; Linux and Windows support is written but not yet tested, and user test reports are welcome on GitHub Issues.

## Long description

Video Studio makes videos for you without paid AI services. Ask for "a 60-second reel of our new feature" or "a demo of our app for the website". It shows a menu of video types, asks a few questions (format, length, voice, captions, brand), writes the storyboard, then produces the video:

- **Software demos:** the real web app recorded live with scripted clicks and typing. Desktop versions get camera moves; mobile versions are a full-screen iPhone showing only the product. It can even record a voice agent's spoken replies.
- **Blog or article to video, shorts and reels, feature launches, tutorials and image slideshows**, built from title, bullet, quote and stat cards, images with slow pans, and live app footage.
- **Sound:** 12 open-source voices (Kokoro-82M), royalty-free background music composed for each video and kept soft under the voice, subtle sound effects, and captions burned in or as an `.srt` file.
- **Full-length and "instant" (about 50 s) cuts** from the same recordings.
- **Safeguards:** it hides admin-only or unreleased features, refuses a take if a forbidden word appears on screen, and uses sample data only.

Requirements: Node.js 18+, Python 3.10–3.12 (or uv), ffmpeg, and Chrome or Edge (or a downloaded Chromium). A one-time installer and a `doctor` check set everything up and say exactly what is missing.

**Platform status:** tested on macOS. Linux and Windows are supported in code (installers for both, headless recording without a display) but not yet tested. Users are invited to file platform test reports on GitHub Issues, and fixes are verified and applied by the maintainer.

## Data, privacy and what it runs (for reviewers)

- **Local processing.** Narration (Kokoro via onnxruntime), music and effects (generated by numpy) and rendering (ffmpeg) all run on the user's machine. No video, audio, script or page content is sent to any service by the plugin.
- **Network use:**
  - **Installer:** it downloads the Kokoro voice model from the kokoro-onnx GitHub release, SHA-256 verified, and packages from npm and PyPI.
  - **Recording:** the browser opens only the URLs in the user's storyboard.
  - **Optional:** Playwright's Chromium download, only if neither Chrome nor Edge is installed.
- **No telemetry.** The plugin collects and sends nothing.
- **What it executes:**
  - Node and Python scripts in the plugin folder.
  - A Chromium-based browser via playwright-core, with its own profile in the plugin's data folder (not the user's browser profile).
  - ffmpeg.
  - The installers (`install.sh`, `install.ps1`) change only the plugin folder and the data folder (`~/.local/share/video-studio` or `%LOCALAPPDATA%\video-studio`). They never install system packages; the doctor prints the command for the user to run.
- **Credentials.** The skill never types passwords. When an app needs a sign-in, the user signs in themselves in the recorder's window.
- **Page scripts.** During recording the plugin injects helpers into the recorded pages:
  - it hides chosen elements;
  - it replaces the microphone with a silent stream that plays only the user's own audio clips, for voice-agent demos;
  - it logs audio playback so recorded voice replies are placed correctly.

  They run only in the recorder's own browser, never in the user's normal browser.
- **Responsible use built in:**
  - sample data only;
  - narration claims must be visible on screen;
  - synthetic voices are never presented as real people;
  - no face or voice cloning without the owner's consent (planned features will label output as AI-presented).

## Step 0: permission first (restricted category)

Anthropic's Software Directory Policy lists **"AI generation of video, audio, or non-design images"** as restricted: such software needs Anthropic's written permission. Video Studio generates AI voiceovers and videos, so email **directory@anthropic.com** before submitting (draft: `docs/permission-request-email.md`). Submit only after a written yes. Check the exact policy wording first: https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy

## How to submit (claude.ai developer portal)

You need a **paid claude.ai plan** (Pro, Max, Team or Enterprise; on Team or Enterprise an Owner submits) and **GitHub connected** to your claude.ai account. The portal checks that you can push to the repo, so connect the `sudsarkar13` account.

1. Go to **https://claude.ai/directory/manage**, then **Submit new**, then **Plugin bundle**.
2. **Source:** `sudsarkar13/video-studio`. Leave the plugin path empty (the plugin is the repo root) and the branch empty (`main`). Click **Validate**.
3. **Listing details:** read from `plugin.json` and `README.md`. To change them, edit those files, push, and validate again.
4. **Data handling** (answers):
   - Reads or stores personal data? **No.** It records only the app the user points it at, with the user's sample data; files stay on the user's machine.
   - Sends data to services other than declared connectors? **No.** No uploads, no telemetry. It only downloads its own dependencies and the voice model at install.
   - Retention: **none by the plugin.** Outputs are local files the user controls.
   - Intended for under-18s? **No.**
5. **Compliance:** your contact email and the four acknowledgements.
6. **Review and submit:** keep the GitHub push webhook (each push to `main` triggers a scan). For publishing, keep reviewer-publishes. Then **Submit for review**.

**After submitting:**
- Status moves through Scanning → In review → Approved → Published; track it in the portal. There is no fixed review time.
- Contact: directory@anthropic.com.
- **Updates:** raise `version` in `plugin.json` for every release, or users keep the old copy. Each push to `main` is scanned; a reviewer publishes each passing version.
